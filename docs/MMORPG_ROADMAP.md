# 메이플스토리 형태의 서버와 MMORPG 기본 기능 구현 순서

2026-10-07 기준입니다. 현재 구현은 인증, 맵 소속·이동, 수평 발판 물리, 일반 채팅·귓속말과 입력 재실행 보정까지입니다. Monster는 표시·소속 동기화용 기본 객체이며 전투·보상·인벤토리는 아직 없습니다.

## 다음 구현: 서버가 검증하는 포탈과 Monster 생명주기

첫 게임 기능 묶음은 포탈 이동과 Monster spawn/despawn·respawn입니다. 현재 임의 Map ID 테스트 이동과 고정 Monster 표시를 실제 맵 플레이 흐름으로 확장합니다.

- `portals.csv`에 소속 Map, Portal ID, 위치·사용 거리, 대상 Map과 대상 spawn을 정의합니다.
- PortalRequest는 대상 좌표 대신 Portal ID와 현재 입장 식별자를 전송합니다.
- 서버가 현재 Map·입장 번호·포탈 존재·거리·사용 조건과 재사용 간격을 검사합니다.
- 성공 시 기존 Map 퇴장 → 새 Map 지형·초기 상태 → 객체 동기화 순서를 유지합니다.
- 임의 Map ID 전환은 테스트 모드에서만 허용하도록 구분합니다.
- Monster 정의와 런타임 인스턴스를 분리하고 Map별 spawn 지점·수량·respawn 시간을 관리합니다.
- MonsterState·MonsterLeaveMap을 추가해 제거·재생성·맵 복귀·재접속 상태를 검증합니다.

완료 기준은 잘못된 포탈·범위 밖 요청·이전 맵 요청의 거절, 다른 맵 상태 미전달, 입력 기록 초기화, Monster 중복 생성 방지와 tick 기반 respawn입니다.

## 이후 구현 순서

| 순서 | 기능 | 서버가 검증할 기준 |
|---:|---|---|
| 1 | 포탈·Monster 생명주기 | 맵 소속·거리·입장 번호·spawn 수량·respawn 시간 |
| 2 | Player·Monster HP/MP와 기본 공격 | 공격 간격·방향·서버 위치 기준 범위·대상 생존·요청 중복 |
| 3 | 피격·사망·복귀·경험치·레벨 | 피해 계산·사망 중 행동 차단·보상 1회 지급·레벨 기준 |
| 4 | 드롭·획득·인벤토리·메소 | Map 소속·획득 거리·소유 조건·중복 획득·슬롯·수량 |
| 5 | 캐릭터 저장과 재접속 복원 | 비동기 DB 처리·트랜잭션·중복 완료 방지·저장 실패 재시도 |
| 6 | Channel 최소 런타임과 실제 UI | 객체·일반 채팅 격리·전역 중복 검사·귓속말·입력 라우팅 |
| 7 | 경사 발판·사다리·드롭 점프와 스킬 | 이동 상태 전환·입력 검증·서버/클라이언트 물리 일치 |
| 8 | NPC·상점·퀘스트·파티 | 거래·재화·진행 조건·파티 권한과 보상 범위 |

HP·MP, 경험치와 아이템은 클라이언트가 확정하지 않습니다. 클라이언트는 행동을 요청하고 서버 결과를 표시합니다. 공격과 획득의 중복 요청 번호를 검사해 피해·보상이 두 번 적용되지 않게 합니다. 전투 중 이동은 현재 서버 확정 위치와 Map tick에 연결합니다.

저장은 GameServer의 비동기 DB 작업 흐름을 확장합니다. 런타임 상태 변경과 DB 완료 결과를 구분하고 오래된 작업이 새 접속 상태를 덮지 않도록 캐릭터별 저장 버전을 사용합니다. 테스트 계정 초기 SQL과 운영 데이터 변경 절차를 분리합니다.

Channel·UI 설계는 [CHANNEL_UI_DESIGN.md](CHANNEL_UI_DESIGN.md)에 있습니다. 현재 Map이 이미 콘텐츠 격리 단위이므로 기본 전투·보상 검증을 먼저 연결할 수 있습니다. Channel 구현 때 Monster·드롭 런타임을 Channel별 Map 인스턴스로 유지합니다.

## 지속 검증

새 기능은 독립 규칙 검증 → 실제 두 클라이언트 패킷 검증 → 지연·재접속·맵 전환 검증 순서로 추가합니다. 이동 보정·일반 채팅·귓속말·Free 회귀는 유지합니다. 계정 접속 시도 제한과 실제 운영용 인증·전송 보호도 별도 묶음으로 보강합니다.
