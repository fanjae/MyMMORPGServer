# 주변 전송·장비·드롭·종료 정책 후속 설계 — 2026-10-15

이번 문서는 후속 구현의 경계를 정한다. 거래와 적응형 이동 표시는 별도로 구현하며, 장비 부위 확대·드롭 추첨·이벤트 주변 전송·공간 격자·영속 피격 저널은 이 문서에서 실제 구현 완료로 표시하지 않는다. 기존 3개 논리 채널의 추가 확장은 대기한다.

## 이동 표시의 선택

클라이언트가 자신의 이동을 즉시 계산하는 기존 구조를 유지한다. 상대의 행동 재현과 표시 보정은 RTT 측정, RTT 변화량, 상대 행동의 도착 간격 변화에 맞춰 조절한다. 본인 캐릭터의 서버 권위 이동·입력 재실행은 이번 범위에 추가하지 않는다.

- 왕복 측정: 인증된 게임 연결에서 1초 간격의 번호 왕복을 사용한다. 응답 수신 시각은 메인 스레드 큐 진입 전에 기록한다. 측정값에는 클라이언트 송신 대기와 서버 응답 처리 대기가 포함될 수 있다.
- RTT는 상대 플레이어의 발신자→서버→수신자 전체 지연이 아니다. RTT/2를 상대의 정확한 편도 지연이나 표시 시간을 복원하는 값으로 사용하지 않는다.
- 표시 버퍼: 기본·최소 200ms, 최대 400ms. 목표값은 200ms + 도착 간격 편차의 2배 + RTT 편차의 2배로 제한한다. RTT 편차는 최소 3개 표본 이후 사용한다. 지속적으로 높은 일정한 RTT에 버퍼를 같은 양만큼 더하지 않는다.
- 버퍼 증가는 초당 최대 500ms, 감소는 초당 최대 20ms로 제한한다. 실제 재현 tick을 과거로 되돌리지 않는다.
- 정속 이동도 1초 확인 주기를 사용한다. 따라서 마지막 수신 직후부터 100ms만 예측하고 멈추면 정상 이동을 끊게 된다. 1초의 정상 확인 주기 뒤 추가 예측만 100~200ms로 제한한다.
- 재수신 복구는 새 기준 상태에서 시작하고, 큰 위치 차이·리스폰에는 기존 즉시 위치 보정을 유지한다. 완전한 전역 시계 동기화나 서버 과거 위치 판정 보정은 구현하지 않는다.
- 검증 지표: RTT·변화량·실제 표시 버퍼·상대 도착 간격 편차, 정지 시점 오차, 재수신 위치 보정, 입력→상대 표시 지연. 마지막 항목은 RTT 값만으로 대체하지 않는다.

Unity 문서는 보간 버퍼가 불규칙한 도착을 흡수하면서 추가 표시 지연을 만든다고 설명한다. 현재 200ms 행동 송신과 1초 확인 주기를 먼저 보존하고 매개변수는 실제 체감·원격망 측정 후 조정한다. 참고: https://docs-multiplayer.unity3d.com/netcode/2.0.0/learn/clientside_interpolation/

## 플레이어·공격·피격 관심 범위

몬스터·드롭의 현재 16m 목록과 플레이어 이벤트의 관심 범위를 분리해 측정한다. 첫 구현은 단순 거리 검색으로 시작하고 목록 계산 시간·대상 수·전송량을 기록한다. 공간 격자는 후보 검색이 실제 병목인 경우에 도입한다.

| 상황 | 다음 구현의 전달 규칙 |
|---|---|
| 상대가 범위에 진입 | PlayerEnter와 현재 위치·방향·생존·장비 외형·전투 중단 상태를 먼저 보낸 뒤 후속 이동 행동을 허용 |
| 상대가 범위에서 이탈 | PlayerLeave로 표시를 제거하고 해당 수신자의 이동·공격 대기 사본을 정리 |
| 같은 맵 재입장·채널 이동 | generation 변경으로 이전 관심 목록·조립 중 목록·대기 행동을 폐기 |
| 공격자가 보이고 대상은 범위 밖 | 공격자의 휘두르기는 표시할 수 있으나 보이지 않는 대상의 상세 상태를 새로 노출하지 않음 |
| 대상이 보이고 공격자는 범위 밖 | 대상의 확정 HP·피격은 전달하고, 원인을 표시하기 위해 범위 밖 공격자 전체 객체를 강제 생성하지 않음 |
| 양쪽 모두 보임 | 동일 사건 번호로 휘두르기·대상 피해를 연결. 이동 표시 시간선과 공격 이벤트의 재생 기준을 함께 정의 |
| 플레이어 자신의 피격 | 자신의 저장 상태·복구 상태는 관심 범위 필터와 무관하게 전달 |
| 일반 채팅·귓속말 | 현재 같은 채널·맵 채팅 및 서버 전체 귓속말 규칙을 별도 유지. 전투 AOI 변경에 묶어 암묵적으로 변경하지 않음 |

순간 위치만으로 필터하면 새 대상의 기준 상태가 누락될 수 있다. 진입 초기 상태 → 행동의 순서를 보장하고 수신자의 generation을 적용한다. 경계가 흔들릴 때는 진입·이탈 반경을 달리하는 방안을 비교하되 정확한 공격·획득 가능 거리와 표시 관심 범위를 혼동하지 않는다.

몬스터·드롭 객체 재사용은 표시 객체를 숨겨 풀에 반환하는 방식으로 검토한다. 재사용 시 ID·revision·피해 숫자·죽음 타이머·보간 상태·재질 참조를 모두 초기화한다. 다른 몬스터의 이전 피해나 이동이 재사용 객체에 남지 않는 검사가 필요하다. 이번에는 풀을 구현하지 않는다.

## 장비·카탈로그·능력치

- 아이템 정의: ID, 분류, 최대 중첩, 허용 부위, 착용 조건, 기본 능력치, 거래 가능 여부, 표시 정의 버전을 관리한다. 소유 인스턴스: 고유 ID, 소유자, 아이템 ID, 강화·개별 옵션을 관리한다.
- 장비 부위는 무기·모자에 상의·하의·신발·장갑·보조무기를 추가할 수 있는 고정 식별자로 정의한다. 반지처럼 같은 부위가 여러 칸인 경우 장착 위치와 부위 종류를 구분한다.
- DB는 item_definitions의 부위·능력치 데이터와 character_equipment의 부위 제약을 이관한다. 현 ck_instance_item과 무기·모자 전용 제약을 그대로 둔 채 아이템 ID만 추가하지 않는다.
- 능력치 계산은 기본값 → 장비 합산 → 비율 보정 → 상하한 제한 순서로 고정한다. 최종 능력치는 서버가 계산하고 클라이언트는 표시용 값을 받는다.
- 착용 트랜잭션은 슬롯·장착 위치·계산된 최대 HP/MP·현재 수치 제한·revision을 함께 확정한다. 최대치 증가를 자동 회복으로 취급하지 않으며 사망 중 장비 변경으로 부활시키지 않는다.
- 패킷은 부위 수와 레코드 목록을 명시하는 새 버전으로 확장한다. 현재 고정 2부위 snapshot과 거래의 장비 소유권 처리를 함께 회귀 검사한다. DB 영수증의 저장 형식도 버전을 고정해 과거 거래 조회를 깨뜨리지 않는다.
- UI는 부위별 칸·교체 예상 능력치·착용 불가 사유를 표시한다. 거래 중에는 변경 조작을 차단하고 선택·제안과 실제 인벤토리 변경을 구분한다.

## 몬스터별 드롭 데이터와 추첨 결과

설정 레코드는 monster_definition_id, entry_id, item_id, min_quantity, max_quantity, probability_ppm, roll_group, catalog_version으로 구성한다. 확률 단위는 정수 0..1,000,000으로 통일한다.

검증은 존재하지 않는 몬스터·아이템, 수량 0·역전·최대 중첩 초과 처리, 중복 entry_id, 배타 그룹 확률 합, 최대 생성 개수와 필드 상한을 포함한다. 독립 추첨과 배타 그룹을 구분하고 설정 오류는 시작 시 거절한다.

몬스터 사망 사건마다 한 번 추첨한 결과에 드롭 ID·아이템·수량·설정 버전을 연결한다. 지급 재시도나 결과 조회는 다시 추첨하지 않는다. 서버 재시작 후 필드 드롭을 유지해야 한다면 사망 사건과 추첨 결과 자체를 영속화하는 별도 범위가 필요하다. 현재 메모리 드롭은 재시작 후 복원하지 않는다.

장비 드롭은 수량마다 인스턴스를 생성한다. 소유 캐릭터 잠금 → 기존 지급 결과 확인 → 필요한 모든 슬롯 확보 → 인스턴스 생성 → 슬롯 연결 → 지급 기록과 revision 커밋의 순서로 처리한다. 공간 부족은 전체 실패로 처리하고 일부 장비만 지급하지 않는다.

필수 검사는 동시 획득, 같은 드롭 재요청, 장비 인스턴스 중복, 빈 슬롯 부족, 인스턴스 생성 후 SQL 실패, 커밋 직후 응답 유실, 조회·재접속에서 같은 인스턴스 번호 유지다. 거래로 소유자가 바뀐 인스턴스를 과거 드롭 조회가 다시 원소유자에게 지급하지 않는 검사도 포함한다.

## 서버 종료와 미확정 피격

현재 테스트 단계의 결정은 커밋된 피격을 보존하고 미확정 메모리 피격은 종료 시 폐기될 수 있는 정책을 유지하는 것이다. 재접속으로 미확정 피해를 회피할 가능성을 제한 사항으로 남긴다. 영속 피격 저널은 이번에 구현하지 않는다.

다음 정상 종료 절차는 신규 로그인·변경 요청 차단 → 필드 신규 전투 중단 → 진행 중 DB 작업의 제한 시간 있는 배출 → 연결 종료 → DB 작업 스레드 종료로 설계한다. 제한 시간을 넘긴 작업을 성공으로 응답하지 않는다. 이 절차는 강제 종료·전원 장애의 영속 보장을 대신하지 않는다.

운영 단계에서 피해 회피를 허용하지 않기로 정하면 피격 접수 번호·대상·피해·생성 세대·발생 시각·처리 상태를 먼저 영속화한다. HP 변경과 완료 표시를 같은 트랜잭션에서 확정한다. 사망·부활 이후 과거 피해 재생 여부와 처리 만료 시간을 함께 정한다. DB 완전 중단 중에도 접수를 보존하려면 로컬 저널의 손상·재전송·디스크 부족까지 별도 설계해야 한다.

거래는 두 사람의 상태와 거래 영수증을 한 트랜잭션으로 저장한다. 최종 확정 후 응답이 불명확하면 단순 취소로 간주하지 않고 같은 거래 ID로 확인한다. 서버 재시작 뒤에도 영수증과 현재 인벤토리를 조회한다. 거래 영수증은 현재 자동 삭제하지 않으며 향후 보관 기간을 정할 때 오래된 거래를 다시 실행하지 않는 조건을 함께 정의한다.

## 측정 범위

기존 32명/실제 122몬스터의 12초 표본을 기준으로 64명, 120초, 위치 분산 및 한 느린 수신자 조건을 추가한다. 몬스터 상한 128 생성 요청은 유지한다. 이 조건의 통과로 다른 PC·장시간 운영·무제한 확장을 보장하지 않는다.

느린 수신자는 인증 후 한 연결의 다운로드를 약 1KB/s로 제한한다. 나머지 연결의 진행, 서버 송신 대기, 한도 초과의 연결별 격리를 기록한다. TCP 수신 버퍼·커널 버퍼와 서버 애플리케이션 대기열을 구분한다. 실제 결과는 별도 검증 문서에 기록한다.
