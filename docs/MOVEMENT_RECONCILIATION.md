# 지연 환경의 입력 기록·재실행과 원격 보간

2026-10-07 구현입니다. 기존 발판 데이터와 물리 규칙은 유지하고 입력 확인 정보와 클라이언트 보정 흐름을 확장했습니다.

## 수행 범위

기존 클라이언트는 서버 상태 수신 때 예측 상태와 누적 시간을 다시 설정했습니다. 서버는 최신 입력을 여러 20ms tick 동안 사용하므로 마지막 입력 번호만으로 이미 적용된 단계와 미확인 단계를 구분할 수 없었습니다.

MovementReconciliation은 각 로컬 고정 단계의 입력 번호·해당 입력의 단계 번호·방향·점프 유지·짧은 점프 정보를 저장합니다. 서버 상태 수신 시 해당 입력까지 확인된 단계만 제거하고 확정 상태에서 남은 단계를 시간 순서대로 재실행합니다. 수신 때 남은 프레임 누적 시간은 유지합니다.

서버는 클라이언트가 보낸 경과 시간이나 단계 수를 사용하지 않습니다. 현재 서버 tick에서 물리를 계산하고 실제 적용한 입력 번호와 그 입력의 적용 tick 수를 응답합니다. 최신 입력이 여러 패킷으로 바뀐 경우 마지막 입력이 적용되기 전까지 확인 번호와 tick 수를 앞당기지 않습니다.

## 프로토콜 변경

Game version은 5이며 Login version 2는 유지합니다. MovementInput은 기존 22바이트입니다. MovementState는 기존 70바이트 뒤에 `inputTicks u32`와 `jumpHeld u8`를 추가한 75바이트입니다.

| 필드 | 의미 |
|---|---|
| sequence | 마지막 서버 시뮬레이션에 적용된 입력 번호 |
| inputTicks | 해당 입력으로 서버가 진행한 고정 단계 수 |
| jumpHeld | 확정 물리 상태의 점프 유지 비트 |

단계 수는 입력 번호가 바뀐 실제 시뮬레이션에서 1부터 계산하며 같은 입력을 유지하면 증가합니다. BeginMap에서 번호와 단계 수를 초기화합니다. 점프 유지 비트까지 복원해 확인된 점프를 재실행하면서 착지 후 다시 점프하는 문제를 방지합니다. 기존 Game version 4 클라이언트는 ProtocolMismatch를 받으므로 양쪽을 함께 갱신합니다.

## 입력 기록과 초기화

- 최대 512개 고정 단계를 보관합니다. 프레임 지연은 기존처럼 최대 5단계만 처리합니다.
- 기록 한도를 넘기면 예측을 멈추고 새로운 입력이 서버에서 확인될 때 재개합니다. 잘린 기록을 임의로 재실행하지 않습니다.
- 이전 Map·입장 번호·플레이어, 오래된 tick과 확인 번호 및 아직 발급하지 않은 입력 번호의 상태를 무시합니다.
- 맵 변경·연결 종료·새 지형 구성 시 입력과 기록을 초기화합니다. 이전 연결의 이벤트는 NetworkManager의 세션 검사로 먼저 격리합니다.
- respawn은 이전 예측 기록을 제거하고 확정 위치로 맞춥니다.
- 송신과 고정 단계 사이에 짧게 눌렀다 놓은 점프도 다음 물리 단계까지 보존합니다.
- 채팅 포커스·창 비활성·입력 차단 시 중립 입력을 전송하고 대기 중인 짧은 점프를 제거합니다.

로컬 PlayerView는 지연된 원본 snapshot으로 화면을 먼저 이동시키지 않습니다. 서버 좌표 표시는 확정 상태를 사용하고 화면 목표는 재실행 완료 상태를 사용합니다. respawn과 4 Unity 단위보다 큰 표시 오차는 즉시 맞춥니다.

## 원격 Player

RemoteMovementBuffer는 최대 64개 상태를 보관하고 100ms 뒤의 서버 시각을 기준으로 보간합니다. 표시 시각이 지연 편차 때문에 뒤로 돌아가지 않게 하며 마지막 수신 위치 이후로 외삽하지 않습니다. respawn이나 큰 위치 변경은 버퍼를 초기화합니다. Free 맵의 기존 위치 보간은 유지합니다.

100ms보다 큰 수신 공백은 완전히 숨길 수 없습니다. 그런 구간에서는 마지막 상태에서 대기하거나 새 수신 위치를 따라잡을 수 있으므로 보정 품질을 사람이 확인하는 절차도 유지합니다. 입력 번호와 적용 단계 기준 재실행은 서버와 로컬의 물리 단계 시작 시각까지 동기화하는 방식은 아닙니다.

## 검증과 측정 방법

클라이언트 테스트 프로젝트의 `--reconciliation`은 입력 재실행·중복 확인·짧은 점프·누적 시간·기록 상한·초기화·원격 버퍼·패킷 형식을 검증합니다. 서버 NetworkReliability는 실제 적용 전의 확인 방지, 단계 수, 짧은 점프·최종 유지 비트, 만료 및 맵 초기화를 검증합니다.

`--latency`는 실제 LoginServer·GameServer와 두 클라이언트 사이에 프록시를 넣습니다. 조건은 단방향 0ms, 80±35ms, 150±60ms입니다. 지연은 양방향에 각각 적용합니다. TCP 패킷 순서는 유지하고 지연 대기량도 제한합니다. 이것은 패킷 손실이나 TCP 재전송을 재현하는 테스트는 아닙니다.

이동·점프·착지·벽·방향 전환, 중립 입력 정지와 두 화면의 수렴, Map 변경·재접속을 검증합니다. CSV에는 서버 확정 좌표, 로컬 재실행 좌표, 원격 보간 좌표, 미확인 단계 수와 보정량을 기록합니다. `resetCorrection`은 같은 수신 시점에 단순 상태 초기화를 했다면 필요한 위치 차이이며 별도의 구형 클라이언트를 동시에 실행한 측정값은 아닙니다.

RunIntegration.ps1에 지연 검증을 포함했습니다. `-MeasurementOutputDirectory`로 출력 디렉터리를 지정하면 성공 뒤에도 latency.csv와 latency.out을 남깁니다. 지정하지 않으면 성공한 임시 파일을 기존처럼 정리합니다. 실패 시 trace·stdout/stderr·원인 파일을 보존합니다.

Unity 검증 도구는 실제 OnGUI 포커스에서 Right와 Space가 눌린 상태의 중립 TCP 입력, 재실행 완료 목표 위치와 기존 채팅·정렬을 확인하고 Windows 빌드를 만듭니다. 일반 Editor 모드의 검증이며 창 활성·비활성의 사람에 의한 조작과 체감 평가까지 자동으로 확인한 것은 아닙니다.

## 수동 확인

최신 클라이언트 `Builds/Movement` 폴더를 사용합니다. 최신 서버 두 개를 로컬 테스트 DB와 연결하고 클라이언트 저장소의 두 PowerShell에서 각각 다음 프록시를 실행합니다. 게임 TCP만 지연시키며 로그인은 원래 7776에 연결합니다.

```powershell
dotnet run --project .\Tests\MapLocalIntegration\MapLocalIntegration.csproj -- --proxy --listen=27777 --delay=150 --jitter=60
```

```powershell
dotnet run --project .\Tests\MapLocalIntegration\MapLocalIntegration.csproj -- --proxy --listen=27778 --delay=150 --jitter=60
```

두 프록시의 READY를 확인한 뒤 클라이언트를 서로 다른 테스트 포트로 실행합니다. Host는 127.0.0.1, Login Port는 7776을 사용합니다.

```powershell
Start-Process .\Builds\Movement\MyMMORPGClient.exe -ArgumentList '--test-game-port=27777'
Start-Process .\Builds\Movement\MyMMORPGClient.exe -ArgumentList '--test-game-port=27778'
```

`--test-game-port`를 지정하지 않으면 서버가 안내한 원래 게임 포트에 연결합니다. 명시한 값은 1..65535 한 개만 허용합니다. 프록시는 로컬 수신만 사용하고 연결이 종료되면 다시 수신 대기하므로 클라이언트 재접속을 확인할 수 있습니다. 검증을 마치면 클라이언트를 종료하고 두 프록시에서 Ctrl+C를 누릅니다. 프록시 재접속과 지연 TCP 보존은 `--proxy-smoke`로 별도 검증합니다.

두 창에서 지속 이동·짧은 점프·방향 전환, 채팅 후 연속 입력, Esc 복귀, 다른 앱으로 전환·복귀를 확인합니다. 본인 화면이 오래된 서버 위치로 먼저 튀지 않는지, 상대 화면의 수신 공백과 따라잡기가 허용 가능한지 확인합니다. 지연 없는 최신 빌드의 기본 접속·이동·채팅도 함께 확인합니다.
