# 2026-10-15 포커스·적응형 이동 표시·플레이어 거래

## 구현

3D 프로토콜을 12로 올렸다. 2D 6과 로그인 2는 유지한다. 기존 테스트 DB에는 005_trade.sql을 추가 적용했다. 기존 DB 전체 초기화는 하지 않았으며 테스트용 HP·계정만 검사 종료 시 정리한다.

상대 이동은 1초 간격 ping/pong의 SRTT·RTT 변동과 실제 행동 도착 간격으로 200~400ms 표시 버퍼를 조절한다. 기본 송신 간격 200ms를 유지한다. 버퍼 목표는 200ms + 도착 지터의 2배 + RTT 변동의 2배이며 상한을 적용한다. RTT 변동은 3개 표본부터 사용한다. 버퍼 증가는 초당 500ms, 감소는 초당 20ms로 제한한다. 일정한 높은 RTT를 그대로 표시 지연에 더하지 않는다. 본인 입력은 즉시 적용하는 기존 동작을 유지한다.

기존 1초 체크포인트 이후 추가 예측 시간은 100ms + RTT/4를 100~200ms로 제한한다. RTT/2를 정확한 편도 지연으로 가정하지 않는다. 재접속은 측정 상태를 초기화하며 이전 연결의 측정 응답은 번호로 거절한다. HUD와 입력 진단에 RTT·변동·버퍼·도착 지터를 기록한다.

거래는 같은 채널·맵의 살아 있는 지상 플레이어끼리 요청/수락한다. 인벤토리 슬롯 최대 6개와 메소를 제안하며 어느 한쪽이 변경하면 양쪽 최종 확인을 초기화한다. 편집 중 이동·공격·인벤토리 변경을 제한한다. 최종 확정 전 취소·피격·연결 해제·만료는 거래를 취소한다. 확정 중에는 임의 취소하지 않는다.

DB에서 캐릭터 ID 순서로 두 소유자 행을 잠근다. 양측 revision·수량·메소·장비 인스턴스·빈 슬롯을 다시 검증한다. 양쪽 제안을 먼저 제거한 복사본에 지급을 계산하므로 빈 슬롯이 없는 장비 맞교환도 가능하다. 양측 슬롯·메소·장비 소유권·revision과 거래 영수증을 한 트랜잭션으로 커밋한다. SQL 실패는 전부 롤백한다. 같은 거래 ID와 같은 요청은 다시 지급하지 않으며 같은 ID의 다른 내용은 거절한다.

커밋 결과가 불명확하면 같은 거래 ID로 1/2/4/8초 간격으로 재시도한다. 양측이 연결을 끊어도 서버의 DB 작업은 계속 처리한다. 클라이언트는 미확정 거래 ID를 서버·캐릭터별로 저장하고 재접속 시 조회한다. 서버 메모리에 없는 거래는 DB 영수증과 현재 인벤토리를 조회한다. 영수증 자동 삭제는 아직 구현하지 않는다. 미래 프로토콜 변경 시 현재 250바이트 저장 형식도 이관해야 한다.

Windows 창 키 이벤트의 키 코드와 문자 이벤트가 같은 누름을 중복 실행하지 않도록 버튼 게이트를 추가했다. 포커스 보완과 함께 새 누름만 공격·획득·인벤토리 조작으로 처리한다.

## 실제 실행 파일과 사용자 직접 조작

Computer Use로 같은 PC의 두 Unity 실행 파일을 조작했다. 16회 창 전환 후 두 창이 계속 실행됐고 비활성 창의 inputAllowed/uiInputAllowed가 false인 것을 기록했다. 복귀 후 J와 왼쪽 Ctrl의 새 입력이 서버 공격 결과로 전달됐다. 목검 착용 상태의 25 피해와 상대 화면 사건 전달을 확인했다. 네이티브 종료가 재발하지 않은 이번 표본을 모든 환경의 근본 해결 보장으로 확대하지 않는다.

Archer(2001) 요청 → Magician(1002) 수락 → Magician의 파란 물약 1개·메소 10 등록 → 양측 최종 확인을 실제 버튼으로 진행했다. 거래 5119776665993572796이 Completed로 끝났고 DB 메소는 1002가 1200→1190, 2001이 1300→1310으로 바뀌었다. 파란 물약은 각각 8→7, 7→8이었다. 이후 슬롯 드래그 저장도 확인했다. 최종 왼쪽 거래 패널과 오른쪽 인벤토리 동시 표시를 다시 확인했다.

Computer Use API에는 키 유지와 마우스를 누른 채 창을 바꾸는 동작이 없어 사용자가 직접 수행했다. 사용자 결과: 새 입력 전 공격 재개 없음, 이전 드래그 취소, 새 드래그 정상. 최종 버튼 게이트 빌드의 J 5초 유지 → 놓기 → 1초 뒤 새 누름도 사용자가 반복 공격 없이 동작했다고 응답했다. 로그에는 다른 이동·공격도 섞여 있으므로 전체 공격 건수를 이 단일 검사 횟수라고 주장하지 않는다.

이전 10월 14일의 공격·인벤토리·장애·표시 비용 검사는 당시 문서에 보존한다. 이번 작업에서 새로 수행한 검사와 혼합해 모두 재수행했다고 쓰지 않는다.

### 64명·120초의 실제 서버 부하

각 조건에서 128몬스터 생성을 요청했고 지형상 유효한 실제 몬스터는 122마리였다. 64명 모두 공격을 0.6초 간격으로 시도했다. 서버는 일반 동작이므로 몬스터 추적·피격·사망·드롭도 함께 발생했다. 각 표본은 로그인·위치 준비 이후 약 120초이며 바이트는 검사 클라이언트들의 애플리케이션 패킷 합계다. TCP/IP 헤더·재전송을 포함하는 회선 사용량은 아니다.

| 조건 | 수신 합계 | 초당 수신 합계 | 몬스터 목록 | 공격 이벤트 | 공격 시도 |
|---|---:|---:|---:|---:|---:|
| 64명 같은 위치 | 242,491,328B | 2,020,361.9B/s | 111,494,336B | 38,735,872B | 12,352 |
| 64명 4개 위치 분산 | 218,102,656B | 1,817,318.2B/s | 88,586,784B | 38,936,576B | 12,416 |

양쪽 모두 정상 64명 연결·생존·전투 중단 해제·클라이언트 송신 대기 해소를 확인했다. 표시 몬스터는 같은 위치 91, 분산 101/64/75/49였다. 몬스터가 움직이는 서버이므로 이를 고정 반경의 정확한 포함·제외 경계 검사로 해석하지 않는다.

서버 프로세스 로그 전체(로그인 준비 포함)의 최대 tick 계산은 같은 위치 1.878ms, 분산 2.352ms였다. 최대 tick 지각은 모두 18ms, catch-up 한도 도달은 0이었다. 송신 대기 표본 최고 합계는 1,097,856B/679,600B이며 정상 연결의 송신 실패·이동 큐 초과는 없었다. 이는 서버 합계 표본이며 개별 연결의 메모리 상한과 구분한다. 근거는 artifacts/load-long-2026-10-15.log 및 field-validation-2026-10-14/GameServer-day15-long-128-64-{same,spread}.out이다.

분산 시 몬스터 목록은 약 20.5% 감소했지만 공격 이벤트는 거의 같은 규모다. 이번 64명·122몬스터 범위에서도 tick 계산은 20ms 예산 안에 있으므로 공간 격자 도입은 보류한다. 플레이어·공격·피격 이벤트의 주변 전송을 다음 우선 범위로 유지한다. 120초는 장시간 운영·다른 PC·무제한 확장의 보증이 아니다.

### 느린 수신자

64명 중 한 명의 인증 후 다운로드를 약 1KB/s로 제한했다. 그 연결은 서버 송신 큐 상한 1,048,576B에 도달해 종료됐다. 오류 로그의 마지막 대기량은 1,048,567B였다. 나머지 63명은 약 120초 동안 연결·생존·전투 진행·송신 대기 해소 검사를 통과했다. 정상 63명의 수신 합계는 237,531,357B, 약 1,978,919.9B/s였다. 느린 연결의 수신량은 이 합계에서 제외했다.

프로세스 로그 최대 tick 계산은 2.280ms, 지각 17ms, catch-up 한도 도달 0이었다. 송신 대기 표본 최고 합계 1,722,421B는 여러 연결의 합계이므로 개별 연결의 1MB 상한을 넘겼다는 뜻이 아니다. TCP 커널 버퍼 크기까지 정확히 측정한 결과로 해석하지 않는다. 근거는 artifacts/load-slow-2026-10-15.log와 GameServer-day15-slow-128-64-same.{out,err}다.

### 공중 높이의 실제 키 입력

입력 도구의 호출 시간 안에 공중 위치를 관찰할 수 있도록 서버 데이터 복사본에만 jumpSpeed=64, gravity=8을 적용했다. 실제 Space 후 실제 J를 입력했으며 공격 응답 직후 기록은 grounded=false, Y=248.496서버단위(약 12.425m), 대상 Y=0, XZ 거리는 30단위(1.5m)였다. Miss·피해 0을 양측 사건 기록에서 확인했다. 착지 후 같은 XZ·방향에서 새 J는 Hit·25 피해·대상 HP35였다. 원본 data CSV는 수정하지 않았다.

이는 실제 키로 높이 차이 1.5m 초과 시 거절됨을 확인한 검사다. 기본 점프 수치에서 1.5m 바로 위의 짧은 순간을 맞춘 실제 입력 검사는 아니다. 정확한 경계는 기존 자동 규칙 검사와 구분한다. 근거는 day15-air-{2001,1002}/Logs/attack-events.jsonl 및 input-probe-events.jsonl이다.

### 종료 정리
