# 발판 및 횡스크롤 이동 설계안

2026-10-05 작성한 최소 횡스크롤 이동 설계 기록입니다. 이후 발판·벽 데이터와 독립 물리뿐 아니라 서버 Map tick·신규 패킷·Unity 입력도 연결했습니다. 아래 제안 중 현재 적용한 구체적인 wire format과 테스트 결과는 [PLATFORM_NETWORK.md](PLATFORM_NETWORK.md), 데이터 및 독립 물리는 [PLATFORM_MOVEMENT.md](PLATFORM_MOVEMENT.md)를 기준으로 확인합니다.

## 1. 오늘 작업 범위

최신 Unity 두 클라이언트의 자유 이동과 위치 보정을 확인한 뒤 발판 데이터와 충돌 규칙을 정리했습니다. 이어서 데이터 로더와 독립 이동 시뮬레이션을 구현하고 자동 테스트를 수행했습니다. 실제 접속 Player에 적용할 서버 tick과 Unity 이동은 다음 단계에서 연결합니다.

첫 구현은 수평 발판, 위에서 내려올 때만 착지하는 발판, 사각형 벽 및 천장으로 제한합니다. 경사, 사다리, 로프, 아래 점프, 이동 발판, 발판 생성·제거와 캐릭터 간 충돌은 이후 단계입니다. 위아래 자유 이동을 제거하는 시점은 발판 이동이 서버와 Unity 양쪽에서 동작하는 단계로 잡습니다.

## 2. 좌표와 캐릭터 영역

| 항목 | 제안 |
|---|---|
| 좌표축 | 기존과 같이 오른쪽 +X, 위쪽 +Y |
| 단위 | 서버 20단위 = Unity 1단위 유지 |
| Player 위치 | 현재 패킷과 Sprite의 중심 좌표 유지 |
| 임시 충돌 영역 | 중심 기준 가로 12, 세로 12 서버 단위 |
| 발 위치 | 중심 X, 중심 Y - 6 |
| 발판 상태 | footholdId 0은 공중, 양수는 현재 접촉 발판 |
| 맵 경계 | 충돌 영역 전체가 경계 안에 들어오도록 검사 |

현재 사각형의 Unity 크기는 0.6이므로 임시 충돌 영역 12단위와 일치합니다. 실제 아바타 크기와 충돌 영역은 추후 별도 데이터로 관리합니다. 카메라는 현재 로컬 Player를 따라가는 방식을 유지합니다.

현재 maps.csv 경계는 Player 중심의 범위입니다. 충돌 영역 전체를 검사하는 단계부터 반폭·반높이를 고려하므로 같은 경계 값에서도 실제 중심 이동 범위가 줄어듭니다. 이 의미 변경은 문서, 서버, 클라이언트와 경계 테스트를 함께 수정합니다.

서버 물리 상태는 소수 좌표와 속도를 보관합니다. 전송용 좌표를 다시 물리 상태에 대입하지 않습니다. 다음 프로토콜의 위치·속도는 서버 단위의 1/1000을 나타내는 int64 정수로 직렬화하는 안을 사용하며, 경계와 발판 끝점은 기존 int32 서버 단위를 유지합니다. 변환은 overflow를 검사하고 정확히 절반인 값은 0에서 먼 방향으로 반올림하는 규칙을 양쪽에 적용합니다.

## 3. 데이터 구조

### 맵 이동 설정

maps.csv의 기존 필드는 자유 이동 모드에 유지합니다. 횡스크롤 설정은 data/map_movement.csv에서 Map ID로 연결합니다. 발판은 data/footholds.csv, 벽·천장은 data/colliders.csv로 분리했습니다. 서버는 maps.csv와 같은 디렉터리에서 세 파일을 로딩하고 DB 연결 전에 검증합니다.

| 필드 | 의미 |
|---|---|
| mapId | maps.csv의 Map ID |
| geometryVersion | 정적 지형 데이터 버전, 0은 사용하지 않음 |
| movementMode | Free 또는 Platformer |
| spawnFootholdId | 지상 입장 발판 ID, 공중 spawn은 첫 단계에서 제외 |
| halfWidth / halfHeight | 임시 캐릭터 충돌 영역의 반폭과 반높이 |
| horizontalSpeed | 초당 수평 이동 거리 |
| jumpSpeed | 점프 직후 +Y 속도 |
| gravity | 아래 방향 가속도 크기 |
| maxFallSpeed | 낙하 속도의 최대 크기 |

초기 튜닝안은 반폭·반높이 6, 수평 속도 80, 점프 속도 240, 중력 480, 최대 낙하 속도 320입니다. 이 값은 플레이 감각을 확인하기 위한 제안이며 테스트 결과에 따라 조정합니다. 이상적인 점프 최고 높이는 60단위입니다.

```text
mapId,geometryVersion,movementMode,spawnFootholdId,halfWidth,halfHeight,horizontalSpeed,jumpSpeed,gravity,maxFallSpeed
100000000,1,Platformer,1,6,6,80,240,480,320
100000001,1,Free,0,6,6,80,0,0,0
```

첫 테스트 맵은 100000000이며 100000001은 자유 이동 비교용으로 유지하는 안입니다. Platformer의 점프·중력·낙하 속도는 양수여야 합니다. Free는 기존 maps.csv의 속도와 허용량을 사용하고 발판·중력 설정은 적용하지 않습니다. 클라이언트는 입장 시 전달받은 이동 모드에 따라 입력 처리를 전환합니다.

### 발판

```text
mapId,footholdId,x1,y1,x2,y2,prevId,nextId
100000000,1,-380,-6,0,-6,0,2
100000000,2,0,-6,380,-6,1,0
100000000,3,-140,34,-20,34,0,0
100000000,4,20,74,140,74,0,0
100000000,5,220,80,244,80,0,0
```

위 데이터는 실제 예시 파일에 반영했습니다. Platformer 설정은 준비된 시뮬레이션용 데이터이며 현재 접속 클라이언트는 기존 자유 이동 프로토콜을 유지합니다. 실제 이동 모드 활성화는 서버 tick과 패킷, Unity 입력을 연결할 때 적용합니다.

- footholdId는 Map 안에서 유일한 양수입니다. 다른 Map에서는 같은 ID를 사용할 수 있습니다.
- 첫 단계는 x1 < x2, y1 == y2인 수평 선분만 허용합니다.
- prevId는 왼쪽 끝, nextId는 오른쪽 끝과 연결된 발판입니다. 0은 연결 없음입니다.
- 연결은 서로 반대 방향으로 참조해야 하며 끝점 좌표가 일치해야 합니다.
- 불연속 발판에 prevId/nextId를 지정하지 않습니다. 공중 이동 후 착지로 연결합니다.
- 공유 끝점에서 입장할 때는 가장 작은 발판 ID를 선택하고, 지상 이동에서는 현재 발판과 연결 방향을 우선합니다.

### 벽과 천장

```text
mapId,colliderId,minX,minY,maxX,maxY
100000000,1,220,-6,244,80
```

벽과 천장은 모든 방향에서 막는 사각형으로 별도 관리합니다. 일방향 발판의 위·아래 통과 규칙과 섞지 않습니다. Monster는 첫 단계에서 정적인 현재 좌표를 유지하고 Monster 이동 AI는 포함하지 않습니다. 예시 발판 3과 4는 높이 차 40, 수평 간격 40이며 점프와 발판 이탈을 확인하는 용도입니다.

사각형 상단에서 지상 이동과 점프를 허용하려면 상단에 발판을 함께 정의합니다. 예시 발판 5는 벽 상단을 접지 가능한 영역으로 정의합니다. 사각형 충돌만으로 접촉 발판 ID를 임의 생성하지 않습니다.

### 로딩 검증

- 존재하는 Map인지, ID가 중복되지 않는지, 모든 숫자가 허용 범위인지 검사합니다.
- 발판 길이, 수평 여부, 맵 경계 포함 여부와 연결 참조의 유효성을 검사합니다.
- 사각형의 최소·최대 순서와 맵 경계 포함 여부를 검사합니다.
- spawn 충돌 영역이 경계와 벽 내부를 침범하지 않는지 검사합니다.
- spawn의 발 위치가 spawnFootholdId 위에 있는지 검사합니다. 예시 맵의 (0,0)은 발판 1의 끝점에 입장합니다.
- 같은 높이의 중복 발판이나 내부 구간이 겹친 발판은 거절합니다. 끝점 공유는 허용합니다.
- 모든 파일을 임시 데이터에 로딩한 뒤 전체 검증에 성공한 경우에만 적용합니다.
- 실행 중 지형 수정은 첫 단계에서 지원하지 않습니다.

## 4. 충돌 규칙

### 지상 수평 이동

발판 위에서는 중심 Y를 발판 높이 + 반높이로 유지합니다. 연결된 수평 발판으로 이동하면 접촉 ID를 변경합니다. 연결 없는 끝점을 넘어가면 공중 상태로 바꾸고 중력을 적용합니다. 발판의 지지 판정은 발의 중심 X를 기준으로 합니다.

### 점프와 착지

지상에서 Space를 새로 눌렀을 때 한 번 점프합니다. 공중 점프와 Space를 누른 채 자동 재점프는 허용하지 않습니다. 상승 중에는 일방향 발판을 통과합니다.

하강 중 이전 발 높이가 발판 이상이고 새 발 높이가 발판 이하이면 그 구간에서 착지 후보를 찾습니다. 교차 순간의 X가 발판 구간 안에 있는지 검사합니다. 같은 tick에 여러 발판을 통과하면 가장 먼저 접촉하는 발판에 착지합니다. 같은 접촉 시간의 끝점은 현재 연결 관계와 ID 순서로 결정합니다.

착지 시 중심 Y를 발판 높이 + 반높이로 맞추고 수직 속도를 0으로 설정합니다. 목적지 좌표만 비교해서 발판을 지나치는 방식은 사용하지 않습니다.

### 벽과 천장

이전 충돌 영역에서 새 충돌 영역까지의 이동 경로를 검사해 가장 이른 충돌 지점까지 이동합니다. 수평 충돌은 수평 속도, 천장 충돌은 위쪽 수직 속도를 0으로 만듭니다. 벽 옆의 낙하와 모서리 접촉도 테스트합니다. 처음부터 벽 안에 겹쳐 있는 데이터는 로딩 오류로 처리합니다.

벽 경계에 접촉한 상태와 내부 겹침을 구분하고 경계 접촉만으로 반대 방향 이동을 막지 않습니다. 계산 오차 허용값은 서버 단위 0.000001로 시작하며 발판·벽 판정에서 일관되게 사용합니다. 오차 허용을 패킷별 추가 이동 거리로 사용하지 않습니다.

### 경계와 낙하

좌우 및 위쪽 맵 경계는 캐릭터 영역이 넘어가지 않도록 제한합니다. 아래 경계에 도달한 공중 Player는 서버가 설정된 spawn으로 복귀시키는 안입니다. 이 이동은 일반 속도 초과로 처리하지 않고 Respawn 상태로 상대와 본인에게 전달합니다. 사망·HP 시스템을 추가할 때 낙하 정책은 다시 결정합니다.

## 5. 서버와 클라이언트 책임

| 영역 | 책임 |
|---|---|
| 서버 Map | 입력 적용 순서, 고정 시간 간격 물리 갱신, 발판·벽 충돌과 확정 상태 전파 |
| 서버 Player 이동 상태 | 소수 위치·속도, 접촉 발판, 접지 여부, 마지막 입력 번호와 입력 만료 시간 |
| Unity 입력 계층 | 좌우와 Space 입력 생성, 채팅 포커스·비활성 시 중립 입력 전송 |
| Unity 로컬 이동 | 같은 지형과 규칙으로 예측하고 서버 상태로 보정 |
| Unity remote Player | 수신 상태와 서버 tick을 이용한 짧은 보간 |
| 테스트 UI | 상태 출력과 검증용 조작, 실제 물리 계산은 별도 이동 계층 |

서버 데이터 타입은 FootholdDefinition, MapCollisionDefinition, PlatformMovementSettings로 분리했습니다. PlatformMovementState와 PlatformMovementInput을 이용하는 MovementSimulation이 독립적으로 이동을 계산합니다. Map이 이 계산을 고정 tick마다 호출하는 연결은 다음 단계입니다. Unity는 별도 게임 입력·이동 계층을 추가하고 TestClientController는 상태를 표시하는 역할로 남깁니다.

서버가 입력을 받아 위치를 계산하는 방향을 권장합니다. 클라이언트가 보낸 접지 여부나 발판 ID만으로 착지를 허용하지 않습니다. 기존 자유 이동의 거리 허용량은 Free 모드에 유지하며 점프와 낙하 거리를 같은 제한으로 검사하지 않습니다.

현재 GameServer는 같은 실행 흐름에서 IOCP 이벤트를 처리합니다. Map의 물리 tick도 이 흐름에서 갱신하는 첫 구현을 제안합니다. 별도 물리 스레드에서 기존 Map/Player를 동시에 변경하지 않습니다.

20ms 고정 물리 간격을 사용하고 다음 tick까지 남은 시간을 IOCP 대기 timeout에 반영합니다. 패킷이 계속 들어와도 tick을 실행하며 현재 1초 IOCP timeout에서만 물리를 갱신하지 않습니다. 지연 시 따라잡는 tick 수에 상한을 두고 초과 지연을 기록합니다. 세션·티켓 정리는 기존과 같이 별도의 주기로 유지합니다.

입력이 도착하기 전의 따라잡기 tick에는 이전 입력을 사용하고 새 입력은 다음 tick부터 적용합니다. 새 입력을 과거 tick 전체에 소급하지 않습니다. 연결 종료와 맵 변경도 같은 상태 변경 흐름에서 처리해 제거된 Player를 갱신하지 않게 합니다.

## 6. 프로토콜 확장안

새 opcode 번호는 실제 구현 시 충돌 여부를 확인해 배정합니다. 현재 패킷을 조용히 다른 형식으로 바꾸지 않고 프로토콜 버전을 검사해 이전 빌드를 명시적으로 거절하는 흐름을 함께 추가합니다.

### 지형 초기 상태

맵 입장 응답과 MapInfo 뒤에 지형 버전·이동 설정·발판 및 사각형 데이터를 전송합니다. 각 조각에 Map ID, 입장 세대, 지형 버전, 조각 번호와 전체 개수를 넣습니다. 조각 크기는 uint16 헤더 및 현재 수신 버퍼의 실제 제한 이하로 검증합니다. 선언한 객체 수·조각 수도 상한을 둡니다.

Unity는 지형 전체 수신과 검증을 마친 뒤 이동 입력을 활성화합니다. 초기 객체 패킷은 큐에 보관하거나 지형 완료 뒤 전송하는 방식 중 하나로 순서를 고정합니다. 첫 구현은 서버가 지형 조각 뒤에 Player/Monster 초기 상태를 보내는 순서를 사용합니다. 메모리에 모인 초기 데이터의 총량도 제한합니다.

### 이동 입력

제안 필드는 Map ID, 입장 세대, uint64 입력 번호, 좌우 방향(-1/0/1), 점프 키 눌림 상태입니다. 시뮬레이션의 jumpHeld는 키의 유지 상태이며 false에서 true로 바뀔 때 지상 점프를 시작합니다. 클라이언트 좌표와 클라이언트 경과 시간은 이동 권한의 근거로 사용하지 않습니다.

- 입력 변경 시 즉시 전송하고 방향 유지 중에도 50ms 간격으로 갱신합니다.
- 키를 놓거나 채팅 입력을 시작하거나 창이 비활성화되면 즉시 중립 입력을 전송합니다.
- 서버가 250ms 동안 새 입력을 받지 못하면 수평 입력을 중립으로 바꿉니다. 공중 중력은 계속 적용합니다.
- 입력 번호는 연결 동안 증가합니다. 중복·감소 번호, 다른 입장 세대와 잘못된 입력값은 적용하지 않습니다.
- 점프 키 상태의 변경은 순서대로 처리하고 짧은 누름·해제가 같은 tick 전에 도착해도 점프 시작이 유실되지 않도록 입력 계층에서 보관합니다. 물리 tick 자체를 입력 요청 횟수만큼 실행하지 않습니다.
- 송신 큐에 쌓인 오래된 수평 유지 입력이 키 해제 뒤 계속 적용되지 않도록 미전송 유지 입력을 최신 상태로 합칩니다. 이미 전송한 TCP 입력은 취소할 수 없습니다.

### 서버 이동 상태

본인과 같은 Map의 상대에게 Character ID, Map ID, 입장 세대, serverTick, 적용한 입력 번호, 위치·속도, footholdId, grounded 및 상태 원인을 전달하는 안입니다. 원인은 일반 이동·맵 입장·위치 보정·낙하 복귀를 구분합니다.

서버 상태는 50ms 간격과 중요한 상태 전환 때 전파합니다. 지연된 tick/입장 세대의 상태는 무시합니다. 동일 Map으로 재입장해도 입장 세대가 달라지므로 이전 위치 응답을 구분할 수 있습니다.

첫 예측 구현은 확정 위치와 속도를 적용하고 아직 확인되지 않은 입력을 유지한 뒤 다음 물리 tick부터 예측을 이어가는 보정으로 시작합니다. 입력 재실행 기반 보정은 서버 tick과 입력 적용 시점이 정의된 뒤 추가합니다. 충돌 계산 위치와 화면 보간 위치를 분리해 보간이 벽을 통과하는 물리 판정으로 사용되지 않게 합니다.

## 7. 구현 순서와 통과 기준

1. 데이터 구조와 로더: 예시 맵을 로딩하고 중복·잘못된 연결·벽 안 spawn을 거절합니다.
2. 네트워크와 분리된 이동 시뮬레이션: 고정 시간 입력으로 지상 이동, 점프, 착지, 발판 이탈, 벽·천장, 낙하 복귀를 검사합니다.
3. 서버 Map tick과 입력·상태 패킷: 과도한 입력 횟수가 이동 속도나 점프 횟수를 늘리지 못하는지 확인합니다.
4. Unity 지형 표시와 로컬 예측: 같은 CSV 원본에서 서버가 전달한 지형을 표시하고 발 위치와 발판이 일치하는지 확인합니다.
5. 두 클라이언트 검증: 본인과 상대의 접지·발판·위치가 수렴하고 채팅·비활성·재입장 이후 오래된 입력이 남지 않는지 확인합니다.

주요 테스트는 다음과 같습니다.

- 발판 연결 끝점을 좌우로 통과할 때 Y가 흔들리지 않음
- 상승 중 일방향 발판 통과, 하강 중 첫 접촉 발판 착지
- 한 tick에 여러 발판·벽을 지나는 큰 이동에서도 충돌 누락 없음
- 벽·천장·발판 모서리 접촉과 경계에서 충돌 영역 유지
- 공중 점프와 중복 점프 입력 거절
- 채팅 포커스, 키 해제, 비활성화 및 입력 만료 이후 수평 이동 중단
- 같은 맵 재입장 후 이전 입장 세대의 입력과 상태 무시
- 낙하 복귀를 본인과 상대가 동일한 spawn 상태로 반영
- 같은 Map만 상태 전파, 기존 로그인·채팅·맵 전환 테스트 유지

## 8. 실제 구현 전 사용자와 확인할 항목

기본 추천은 Space 점프, 수평 발판과 사각형 충돌부터 구현하는 것입니다. 위 방향키는 사다리나 포탈이 생기기 전에는 이동에 사용하지 않습니다.

아바타 충돌 크기, 점프 감각과 낙하 시 사망 여부는 아직 실제 게임 정책이 정해지지 않았으므로 위 수치를 임시값으로 사용합니다. 경사·사다리·아래 점프의 도입 순서는 첫 수평 맵 테스트 이후 결정합니다. 오늘은 이 정책을 실제 게임 기능으로 확정하거나 자유 이동 테스트를 교체하지 않습니다.
